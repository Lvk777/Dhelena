## Bloqueio de schema encontrado na primeira ação autorizada

A primeira ação administrativa respondeu HTTP 500 e a transação foi revertida. O log Postgres registrou `invalid input syntax for type bigint` ao receber o ID `PAY...` da Orders API. Leitura de `information_schema.columns` confirmou que `public.orders.mercado_pago_payment_id` está em `bigint` no banco publicado, embora a migration 008 do repositório defina `text`; nenhum dos seis pedidos tem valor nessa coluna. A migration `012_orders_api_transaction_id_text.sql` altera apenas o tipo para `text`, preservando IDs numéricos existentes por conversão decimal. Ela deve ser aplicada conscientemente antes de qualquer nova conciliação. A prévia agora reprova `transaction_id_column_compatible` enquanto o tipo publicado não for `text`. Nenhuma alteração de schema foi feita durante o diagnóstico.
